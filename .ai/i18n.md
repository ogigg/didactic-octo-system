# i18n Guide

> **Document status:** Reference document
> **Purpose:** Define the translation workflow, naming conventions, and namespace rules for the mobile app.
> **Last reviewed:** 2026-04-11

## Library Stack

| Package             | Role                                       |
| ------------------- | ------------------------------------------ |
| `expo-localization` | Reads device locale (`getLocales()`)       |
| `i18next`           | Core translation engine                    |
| `react-i18next`     | React bindings (`useTranslation`, `Trans`) |

**Why this stack:** Industry standard for Expo apps. Type-safe via TypeScript augmentation, supports namespaces, interpolation, and rich text. Adding a new language requires zero code changes — only a new locale directory.

---

## Directory Structure

```
apps/mobile/i18n/
  index.ts              # i18next init — import as side effect: import "@/i18n"
  resources.ts          # Aggregates all namespaces; exports AppResources type
  i18next.d.ts          # CustomTypeOptions augmentation for full type safety
  locales/
    en/
      common.ts         # Shared: nav titles, generic actions, alerts
      home.ts           # Home screen
      explore.ts        # Explore screen
      modal.ts          # Modal screen
      design-system.ts  # Design system screen
```

## Key Naming Schema

### Rules

1. **Namespace = feature/screen** (one file per screen, plus `common` for shared text)
   - File name: kebab-case (`design-system.ts`)
   - Export name: camelCase (`designSystem`)
   - i18next namespace key: camelCase (`designSystem`)

2. **Keys = `section.element`** — two levels maximum for most strings
   - `t("nav.home")` — section `nav`, element `home`
   - `t("step1.title")` — section `step1`, element `title`
   - `t("button.primary")` — section `button`, element `primary`

3. **Root keys** for standalone strings with no logical grouping
   - `t("title")`, `t("welcome")`, `t("intro")`

4. **Cross-namespace references** — always explicit, never implicit
   - `t("action.learnMore", { ns: "common" })`

5. **Interpolation variables** use `{{camelCase}}`
   - `"Token reference for {{mode}} mode"` → `t("tokenReference", { mode: colorScheme })`

### Namespace Inventory

| Namespace      | File                          | Contents                                                                                        |
| -------------- | ----------------------------- | ----------------------------------------------------------------------------------------------- |
| `common`       | `locales/en/common.ts`        | `nav.*`, `action.*`, `alert.*`                                                                  |
| `home`         | `locales/en/home.ts`          | `welcome`, `step1.*`, `step2.*`, `step3.*`, `menu.*`                                            |
| `explore`      | `locales/en/explore.ts`       | `title`, `intro`, `fileRouting.*`, `platformSupport.*`, `images.*`, `theming.*`, `animations.*` |
| `modal`        | `locales/en/modal.ts`         | `title`                                                                                         |
| `designSystem` | `locales/en/design-system.ts` | `title`, `tokenReference`, `section.*`, `colorGroup.*`, `typography.*`, `button.*`, `input.*`   |

### Examples

```ts
// Simple string in current namespace
const { t } = useTranslation("home");
t("welcome"); // "Welcome!"
t("step1.title"); // "Step 1: Try it"

// Cross-namespace
t("action.learnMore", { ns: "common" }); // "Learn more"

// Interpolation
t("tokenReference", { mode: "dark" }); // "Token reference for dark mode"
```

## `useTranslation` vs `Trans`

### Use `useTranslation` + `t()` for:

- Plain strings (no inline components)
- Attribute values (`title`, `placeholder`, `accessibilityLabel`)
- Alert messages
- Any string that does not need formatted spans

```tsx
const { t } = useTranslation("home");
<ThemedText type="titleMd">{t("step1.title")}</ThemedText>;
```

### Use `Trans` for:

- Strings that embed inline React Native components (bold text, links)
- Strings where the translated text wraps part of the content

```tsx
<Trans
  i18nKey="step1.description"
  ns="home"
  values={{ shortcut: "cmd + d" }}
  components={{ bold: <ThemedText type="bodyMedium" /> }}
/>
```

The translation string uses XML-like tags matching the `components` keys:

```ts
"Edit <bold>app/(tabs)/index.tsx</bold> to see changes. Press <bold>{{shortcut}}</bold>...";
```

## How to Add a New Language

1. Create `apps/mobile/i18n/locales/<lang>/` (e.g., `pl/`)
2. Copy all files from `en/` and translate the string values (keep keys identical)
3. Import each namespace in `resources.ts` and add under the new language key:
   ```ts
   import { common } from "./locales/pl/common";
   // ...
   export const resources = {
     en: { common, home, explore, modal, designSystem },
     pl: { common, home, explore, modal, designSystem },
   } as const;
   ```
4. `i18next` will auto-select the language via `expo-localization` device locale, falling back to `"en"`.

No changes needed to any screen file.

---

## How to Add New Translation Keys

1. **Add the key** to the appropriate locale file in `locales/en/`:
   ```ts
   export const home = {
     // ...existing keys
     newSection: {
       title: "My New Section",
     },
   } as const;
   ```
2. **TypeScript** will immediately surface the new key in autocomplete via the `i18next.d.ts` augmentation. Invalid keys are compile errors.
3. **Use it** in the component:
   ```tsx
   const { t } = useTranslation("home");
   t("newSection.title");
   ```
4. If adding a new screen, create a new locale file and namespace following the existing pattern, then register it in `resources.ts`.

## Type Safety

`apps/mobile/i18n/i18next.d.ts` augments i18next's `CustomTypeOptions`:

```ts
import type { AppResources } from "./resources";

declare module "i18next" {
  interface CustomTypeOptions {
    defaultNS: "common";
    resources: AppResources;
  }
}
```

This gives:

- **Autocomplete** on all `t()` key strings in your editor
- **Compile-time errors** for typos or deleted keys
- **Interpolation type inference** (variable names in `{{}}` are checked)
